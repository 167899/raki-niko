# Raki Niko: мобільний магазин

- `mobile/`: застосунок iOS та Android (Expo, React Native, TypeScript), українською.
- `backend/`: WooCommerce і плагін `raky-shop` (API, статуси, зони, реквізити).

## Локальний запуск

```bash
cd backend && npm install && ./start.sh
```

```bash
cd mobile && npm install && npx expo start --web
```

Адмінка: http://127.0.0.1:9400/wp-admin, тестовий менеджер `manager`, пароль задано в `backend/start.sh`.
Дані локального сервера живуть до його зупинки, а замовлення на пристрої після цього не знайдуться.

### На телефоні через Expo Go

Телефон і комп'ютер мають бути в одній мережі Wi-Fi. Вкажіть IP комп'ютера й скануйте QR-код:

```bash
cd mobile && EXPO_PUBLIC_API_URL=http://<IP-комп'ютера>:9400 npx expo start
```

Android-емулятору потрібна адреса `EXPO_PUBLIC_API_URL=http://10.0.2.2:9400`.

## Застосунок

- Екрани: `mobile/src/screens/`, спільні елементи: `mobile/src/components/ui.tsx`.
- Стан магазину, кошик, замовлення на пристрої, сповіщення: `mobile/src/shop.tsx`.
- Навігація, меню й підказки: `mobile/src/nav.tsx`, `mobile/src/components/Overlays.tsx`.
- Телефони й юридичні тексти поки в `mobile/src/content.ts`.
- Іконки згенеровані в `mobile/src/icons.ts` із `@tabler/icons`.

Калібри: товари однієї підкатегорії показуються на одній картці. Наприклад, категорія «Варені», підкатегорія «Раки вершкові». Основні категорії стають чипами на Головній. Смаки задаються окремими рядками з доплатою за кілограм або штуку. Поля є на вкладці «Основне» товару.

## Шлях замовлення

1. Клієнт надсилає замовлення: `Очікує підтвердження`.
2. Менеджер уточнює вагу, ставить `Очікує оплату` і сам повідомляє клієнта: реквізити вже видно в застосунку.
3. Отримавши оплату, менеджер ставить `В обробці`.
4. Після передачі кур'єру: `Передано в доставку`, потім `Виконано`.

Оплата готівкою: менеджер одразу ставить `В обробці`, реквізити клієнт не бачить.

Доставка: сервер шукає будинок у OpenStreetMap і бере ціну із зони. Якщо будинок не знайдено точно або він поза зонами, у замовленні стоїть 0 і суму вписує менеджер. Зони Go2U лежать у `tools/delivery-zones.json` (35 багатокутників, відсортовані за ціною). Публічний сервер Nominatim розрахований на малі обсяги: для запуску варто перейти на платний геокодер.

Реквізити, точки й зони редагуються в WooCommerce → Застосунок.
Суші: опублікуйте товар у категорії «Суші», і вкладка з'явиться сама.

## Ціни зі Skyservice

Синхронізація вбудована в плагін і запускається кожні 10 хвилин.

1. WooCommerce → Застосунок → «Ціни зі Skyservice»: адреса кабінету з адресного рядка після входу, телефон і пароль Skyservice. Точку Спаська плагін обере сам.
2. У картці товару оберіть «Товар у Skyservice». Артикули в касі не заповнені, тому товари зіставляються за номером товару Skyservice. У полі «Додати до ціни» можна вибрати рецепт: його ціна додається до основної, а наявність береться лише з основного товару. «Множник Skyservice» множить суму, наприклад 0.1 для ціни за 100 г при ціні в касі за кілограм. Під полями видно, як складено ціну.
3. «Перевірити зміни» показує, що зміниться, нічого не записуючи. «Синхронізувати зараз» застосовує зміни.

Вхід за паролем, бо API-токени для акаунта Skyservice не ввімкнені. Пароль зберігається зашифрованим ключем із солей `wp-config.php`. Після зміни солей його треба ввести знову. Сесія Skyservice зберігається, і вхід повторюється лише тоді, коли сервер її відхилив. Якщо Skyservice не прийняв пароль, синхронізація зупиняється й більше не пробує ввійти, доки налаштування не збережуть знову: Skyservice блокує вхід після кількох невдалих спроб.

Ціна з каси переноситься як є, без обмежень на розмір зміни. Ціна 0 теж переноситься. Пропускаються й потрапляють у звіт лише товар без ціни в касі й товар, якого немає в касі. Вимкнений у касі основний товар стає «немає в наявності». Одиницю застосунку (г, кг, 100 г, л, мл, порція, шт) задає поле «Одиниця застосунку» в картці товару, а різницю з одиницею каси вирівнює множник.

Публічної документації API Skyservice немає: запити повторюють кабінет Skyservice (`includes/skyservice.php`). Після оновлень Skyservice синхронізація може зупинитися. Тоді в адмінці з'явиться помилка останньої спроби.

На хостингу WP-Cron має запускатися системним cron, а не відвідуваннями сайту.

## Перед публікацією

- Замінити демо-дані у `tools/seed-demo.php`: зони, адреси, реквізити, ціни, фото.
- Перевести тайли карти з публічного сервера OpenStreetMap на комерційного постачальника.
- Перенести акаунти на сервер і додати підтвердження телефону через SMS. Зараз акаунт живе лише на пристрої.
- Підключити вхід через Google і Apple, реферальну програму й push-сповіщення. Зараз статус замовлення оновлюється, лише коли застосунок відкрито.
- Замінити іконку застосунку файлом логотипа у високій роздільності.

## Вебверсія на GitHub Pages

https://167899.github.io/raki-niko/ показує справжній застосунок на вбудованих демо-даних із `mobile/src/demoApi.ts`: сервер їй не потрібен, замовлення зберігаються лише в браузері, підтвердження менеджера імітується.

Оновлення: `./build-pages.sh`, потім коміт і push. Скрипт перезаписує в корені `index.html`, `_expo/`, `assets/`, `demo/`. Новий товар для цієї сторінки додається в `demoApi.ts`.

Статичний прототип лежить у `prototype/`.
